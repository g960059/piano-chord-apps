## 4. 画面のしくみとファイル構成

**画面**
- **楽譜の表示**
  - PR1 では、正解データから `PA.staffSVG(key, cols, {grand:true})` で「和音の骨組み」を描きます。上に小節番号を出し、「じぶんの楽譜もひらいてね」と書きます。
  - PR2 では、本物の楽譜の SVG を足して、骨組みと切りかえて見られるようにします。
- **穴うめ**
  - 和音が変わる所にだけ「？」のボタンを置きます。タップできる幅は 44pt 以上にします。
  - 答えかたは2つです。
    - やさしいモード：3〜4択。まちがいの選択肢は、同じ和音のちがう転回、となりの働きの和音、異名同音のふたご。
    - 受験モード：部品を組み立てる（音度 → 7・9 → 転回 → ◯・斜線・ⅤのⅤ・ツメ）。
  - 調を答える問題、終止の問題、非和声音の問題もつけます。
- **音**：今の `PA.playNote(midi, when, dur, vel)` で鳴らします。「この和音だけ」「この小節だけ」「ぜんぶ」を選べて、鳴っている所を光らせます。テンポは4分音符の数（q）で持つので、スライダーで変えられます。
- **言葉**：画面の言葉はやさしく、分かち書きはしません。むずかしい名前は答えたあとにだけ出します（例：「ドイツの六ともいうよ」）。

**本物の楽譜（PR2）**
- npm の `verovio@6.3.0` を devDependency に入れます（6.4.0 は前日に出たばかりなので避けます）。`tools/build-scores.mjs` で、静的な SVG と、タイムマップ・音の高さの JSON を作ります。
- アプリ本体に入る wasm はゼロで、LGPL の問題もありません。サポートページに「楽譜の図は Verovio（LGPLv3）で作りました」と書くと丁寧です。
- 入力は MusicXML（MuseScore で手入力して書き出す）か、ショパンなら kern をそのまま読みます。ただし kern を読むには Humdrum 入りの `verovio-module-hum.mjs` が要ります。どちらも未検証です。
- 抜粋1つの SVG の大きさ（数十〜数百 KB という見積もり）、タイ・ペダルの扱いは、まだ測っていません。

```
scores/src/<id>.txt            … 手で書く短い書きかた（例：m15 c: Ⅰ q2 [Ⅴ7^2]）
scores/src/<id>.musicxml|.krn  … PR2 の入力

tools/build-scores.mjs         … PR2

```
- `rn` の部品は次のとおりです：`deg` / `form`(7,9) / `inv`(0–3。根音省略形も、はぶいた根音で数える) / `omitRoot` / `borrowed`(◯) / `rootAlt`("-"、ナポリ) / `of`(ⅤのⅤ・◯度調) / `alt5`("down") / `name`(ger6 など) / `tag`(cad64)。
- そのほかに `blank`、`grade`（どの部品で採点するか）、`accept`（別の正解）、`challenge`、`review`（先生がまだ見ていない）を持ちます。
- 記号を文字で持たずに部品で持つと、右上・右下の数字、斜線、◯、2段の記号、ツメを、SVG と HTML で正しく描けます。
